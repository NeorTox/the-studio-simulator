# Cinematic Character Interaction System

## Direction

THE STUDIO now has a dedicated Conversations workspace inspired by the scene composition and character-focused interactions of visual novels. This is a presentation layer over the existing simulation, not an engine migration. The campaign's materialized NPCs, relationships, memories and decision systems remain authoritative.

## First implementation

- A dedicated Conversations route within the existing Life navigation group, with a shortcut from Founder & Personal Life.
- Campaign-backed contact list sourced from `active.world.population.npcs`, with all-people, studio-staff and connected-contact filters.
- A cinematic scene stage, contextual scene descriptions, character dossier and responsive mobile composition.
- Four player approaches: offer support, explore ambitions, agree practical next steps, and challenge a position.
- Topic framing for current work, ambitions, personal life and the entertainment industry.
- Campaign-persistent conversation sessions and bounded transcript history in `active.world.cinematicInteractions`.
- Each selected approach is recorded through `StudioSocialNetwork.interact('PLAYER', npcId, ...)` and `StudioNPCMemory.recordMemory(...)`.
- A player choice therefore updates the actual social graph and NPC memory; the interaction is not an isolated dialogue minigame.
- Browser regression seeds a real campaign NPC and checks route access, dialogue choices, transcript persistence, relationship changes and memory recording.

## Architecture and boundaries

- `studio-ui-interactions.js` owns conversation presentation and session orchestration only.
- `StudioSocialNetwork` remains authoritative for trust, rapport, tension and the relationship graph.
- `StudioNPCMemory` remains authoritative for episodic memories and recall.
- `StudioNPCDecisionConsequences` remains authoritative for the universal autonomous / player-intervention situation system. This first conversation milestone does not fabricate or bypass situation records; deeper conversation-to-situation hooks are a subsequent integration.
- Conversation state is campaign-serializable and bounded to 80 retained sessions and 500 history events.
- Existing world-time, campaign-save and NPC autonomy systems remain unchanged.

## Current limitations

- Initial replies are deterministic, contextual rule-based responses, not generated by an LLM or a fully-authored branching narrative graph.
- The current scene character illustration is a CSS-based visual placeholder. It demonstrates scene composition and responsive layout, but is not the final portrait/sprite pipeline.
- Facial-expression variation, gesture animation, authored scene backgrounds, voiced dialogue, character-specific portrait sets and long multi-stage storylines remain future visual/content milestones.
- The first choice set is a reusable interaction pattern. Later scenarios should expose situation-specific choices and connect them to existing decision/consequence records where appropriate.

## Next milestones

1. Replace the placeholder figure with a reusable character-art system supporting distinct people, wardrobe, poses and emotion states.
2. Build a scene/staging library for office, set, home, public and travel locations.
3. Expand conversations into context-aware branching scenes with interruptions, follow-up appointments, action commitments and outcomes.
4. Connect relevant dialogue to the existing universal decision/consequence engine without duplicating its state.
5. Add mobile interaction QA for scrolling, touch targets, portrait presentation and scene transitions.
